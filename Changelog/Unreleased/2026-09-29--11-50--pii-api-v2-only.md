# Removed
- The Google-DLP-compatible `image:redact` route and the fallback to it: eecc-redact detects only through the ShinrAI PII API v2 (`POST /v2/detect`)
  - The `api`, `project` and `location` settings are gone; existing settings files still load and those keys are ignored
  - `doctor` no longer reports `image:redact`, the chosen route or the Google info types

# Changed
- The key check and `doctor` read everything from the v2 API with the bearer key: `GET /v2/capabilities` (images, OCR languages, models), `GET /v2/usage` (plan, records left) and `GET /v2/types` (personal-data types)

# Fixed
- The settings window on Windows and Linux refused every working key with "this ShinrAI deployment offers no image redaction". It only looked for the Google routes, which ShinrAI moved to `/v1/google/v2/...`; a key is now accepted when `GET /v2/capabilities` says images are served with OCR
- A `/v2/detect` answer whose result failed or is missing is shown as an error with Retry instead of an empty "Nothing detected" review
- HTTP 503 (`degraded_refused`, `queue_full`, `backend_unavailable`) asks to try again instead of claiming the deployment serves no images
